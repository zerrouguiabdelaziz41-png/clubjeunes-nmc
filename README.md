# نادي منبر الشاب المبدع

مشروع واجهة React + Vite متصل بـ Supabase. هذه نسخة تطوير؛ لا ترفعها إلى الموقع المنشور قبل اجتياز الاختبارات.

## المتطلبات
- Node.js إصدار حديث يدعم Vite 8.
- المفتاح العام Publishable الخاص بمشروع Supabase فقط.

## التشغيل على الحاسوب
1. فك ضغط الملف.
2. افتح مجلد المشروع في Terminal أو PowerShell.
3. نفّذ `npm install`.
4. انسخ `.env.example` إلى `.env.local`.
5. افتح `.env.local` وحدد رابط مشروع التطوير/الاختبار في `VITE_SUPABASE_URL`، ثم ضع المفتاح العام المطابق له في `VITE_SUPABASE_PUBLISHABLE_KEY`.
6. لا تستخدم رابط الإنتاج أو بيانات أعضائه للاختبارات المحلية. لا يختار التطبيق مشروعاً افتراضياً عند غياب الرابط.
7. نفّذ `npm run dev` وافتح الرابط الذي يظهر.

## الأمان
- لا تضع `service_role` أو `sb_secret` أو رموز Supabase الشخصية التي تبدأ بـ `sbp_` في ملفات الواجهة أو Google AI Studio أو Cloud Run frontend.
- لا تغيّر أدوار الحسابات من المتصفح. مصدر الدور هو `profiles.role` وسياسات قاعدة البيانات.
- مراجعة طلبات العضوية والأنشطة تتم عبر دوال RPC الإدارية المحمية.

## العضوية والتحقق
- رقم العضوية الرسمي محفوظ في `profiles.membership_number` بصيغة `NMC-YYYY-0001` ويُنشأ عبر مشغّل قاعدة البيانات.
- رمز QR يحتوي رقم العضوية، وليس UUID أو رمز دخول. وهو معرّف فقط ولا يثبت الاعتماد بمفرده.
- دالة `verify_approved_member` تتحقق من الرقم وتعيد الحقول العامة المحدودة: رقم العضوية والاسم والدور، للحسابات المعتمدة فقط.
- ترحيلات العضوية والتحقق مطبّقة بالفعل على قاعدة بيانات المشروع المرتبطة؛ لا حاجة إلى تشغيل ملف SQL يدوياً مرة أخرى.


## تحديث إداري إضافي
- تتضمن بوابة المدير واجهة لتغيير دور الحساب إلى مشرف نشاط أو إعادته إلى عضو عبر الدالة المحمية `admin_set_profile_access`.
- تتضمن واجهة لإسناد الأنشطة إلى المشرفين وإلغاء الإسناد، بالاعتماد على سياسات RLS الموجودة في جدول `organizers`.
- عند إعادة المشرف إلى عضو، تحاول الواجهة إزالة تكليفاته السابقة.
- لا تضع مفاتيح Supabase السرية في الواجهة أو ملفات `.env` التي تُنشر. استخدم المفتاح العام Publishable فقط.

## حالة التحقق والنشر
- نسخة المعاينة على فرع `nmc-development` منشورة على Vercel وحالتها `READY`، وتم التحقق من استجابة الصفحة الرئيسية وملفات JavaScript وCSS والصورة الأساسية بحالة HTTP 200.
- هذا نشر معاينة للتطوير، وليس نشراً رسمياً على Production.
- نجاح بناء Vercel لا يغني عن اختبارات رحلة المستخدم الكاملة. يلزم اختبار التسجيل وتأكيد البريد ورفع الصورة واعتماد العضوية والصلاحيات بحسابي اختبار منفصلين قبل اعتماد الإنتاج.
- لا تُنشئ حسابات اختبار في قاعدة بيانات الأعضاء الحقيقية؛ استخدم مشروع/بيئة اختبار منفصلة.

## ملاحظات تشغيل مهمة

- اسم النادي المعتمد في الواجهات هو «نادي منبر الشاب المبدع».
- رمز QR في بطاقة العضوية يُنشأ كرمز فعلي يحتوي رقم العضوية الرسمي. لا يُعد الرمز وسيلة مصادقة؛ التحقق الحقيقي يتم عبر دالة التحقق العامة المحدودة في Supabase.
- تمت إضافة الاعتمادية `qrcode.react`؛ نفّذ `npm install` قبل `npm run build`.
- لا تضع مفتاح `service_role` أو أي مفتاح سري في ملفات الواجهة أو متغيرات `VITE_`. استخدم المفتاح العام Publishable فقط.
- لم يتم تغيير مخطط قاعدة البيانات أو بيانات الأعضاء في هذه النسخة.


## أرقام العضوية الرسمية (NMC)

أُضيف العمود `profiles.membership_number` والفهرس الفريد ومولّد الأرقام السنوي بصيغة `NMC-YYYY-0001` مع الإبقاء على `profiles.id` (UUID) كما هو. تم التحقق من وجود العمود والمشغّل في قاعدة البيانات المرتبطة، ومن عدم وجود أرقام مفقودة أو مكررة في السجلات الحالية. لا تُعد تشغيل ملف الترحيل يدوياً على قاعدة البيانات المرتبطة.
